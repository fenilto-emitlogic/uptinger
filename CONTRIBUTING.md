# Contributing to Uptinger

Thanks for your interest in Uptinger.

## Reporting bugs & requesting features

Please open a [GitHub Issue](../../issues) — this is the primary and preferred
way to contribute. Include:

- What you expected to happen vs. what actually happened
- Steps to reproduce (for bugs)
- Your Uptinger version / Docker image tag, and relevant logs if applicable

## Pull requests

Uptinger is developed primarily by the Emitlogic team. External pull requests
are welcome, but please note:

- **Every PR is reviewed and merged at the maintainers' discretion.** Opening
  a PR does not guarantee it will be accepted, and it may be modified,
  closed, or asked for changes before merge.
- **`main` is protected.** All changes, including from maintainers, go
  through pull request review — nothing is pushed directly to `main`.
- For anything non-trivial (new features, architectural changes, new
  monitor types, etc.), please open an issue to discuss the approach
  **before** investing time in a PR.
- Small, focused PRs (bug fixes, docs, typos) are the easiest to review and
  merge quickly.
- CI (GitHub Actions) will not run automatically on PRs from forks until a
  maintainer approves the workflow run — this is a deliberate security
  measure, not an oversight.

## Code of conduct

Be respectful and constructive. Issues or PRs that are abusive, spammy, or
off-topic will be closed without engagement.
